Pocket Torrent Privacy Policy

ShireByte Apps · Updated 21 October 2026

Privacy contact: developer.shirebyteapps@gmail.com

Who provides the app

Pocket Torrent is provided by ShireByte Apps. This policy describes the current Android app, its optional browser controls and local media sharing. It explains what the app handles on your device and what is transmitted when you use these features.

Information kept on your device

The app stores torrent metadata and magnet details, chosen file lists, download progress and resume records, storage locations and Android folder grants, media-library entries and exclusions, transfer settings, local device names, and your lawful-use acknowledgement. These records support downloading, recovery and sharing. Torrent details can contain private tracker passkeys; treat them as sensitive.

Browser-control configuration includes an installation-specific hostname, a local Certificate Authority and server certificate, and paired-browser names, pairing/last-use dates, expiration/revocation records and SHA-256 token verifiers. CA and server private keys are non-exportable Android Keystore keys; hardware backing depends on the device. The browser receives a Secure, HttpOnly session cookie after matching a four-digit confirmation code and explicit phone approval. Pairing requests and codes stay in memory and expire after 60 seconds; pending requests include the requesting network address. Local-network media discovery uses a locally generated persistent device identity, not your Android Advertising ID or hardware identifier.

BitTorrent connections

When you add or resume a torrent, the native BitTorrent engine connects to peers and may contact trackers, distributed hash table (DHT) nodes and local peer discovery services. Network participants can see connection IP addresses and ports, protocol peer identifiers, torrent information hashes, and protocol activity such as available pieces or transfer statistics. Downloading can also upload file pieces to other peers. Continued seeding depends on your settings.

Trackers, peers, network operators and other participants are independent of ShireByte Apps and may retain or analyse information they receive. A magnet or torrent file determines some of the services contacted. BitTorrent traffic is not anonymous, and the app does not guarantee encryption for every connection. The current app restricts torrent networking to a bound Wi-Fi network.

Optional browser controls

If you enable browser access, a paired browser on the reachable local network can send torrent commands to your phone. An authorized session can view torrent names, progress, file lists and storage information, manage torrents, and access permitted media-library information. The phone sends this information to the browser to provide the controls you enabled.

Browser controls use HTTPS and authenticated WSS with a private local CA. Verify the complete SHA-256 CA fingerprint against the phone before installing it, and establish trusted HTTPS before comparing the browser confirmation code with the phone. Installing a private root CA grants substantial trust; name restrictions on locally installed roots are not enforced consistently. The CA private key never leaves Android Keystore. Remove the CA from your computers after a security reset, clearing app data, uninstalling or ending use. Resetting security creates a new trust identity and requires pairing again.

Paired-browser credentials expire after 30 days without activity and can be individually revoked on the phone. Disabling access or its timer expiring closes connections and cancels pending pairing without deleting downloads. Pairing normally survives listener restarts. The public HTTP setup portal exposes only setup information, offline help and the public CA certificate/profile on the current Wi-Fi address. HTTP cannot authenticate the certificate download; verify its full fingerprint against the phone before installation. The setup portal stops with web access or a network change. The optional media playback service still uses HTTP independently; browser-control HTTPS does not encrypt media playback or all BitTorrent connections. Do not forward these services to the internet.

Optional media sharing and discovery

When you enable media sharing, devices holding a valid playback or playlist link can request shared file names, library information and file contents. Links act as bearer credentials: anyone holding a valid link may use it while the service is available. Playback uses HTTP without TLS.

If TV discovery (DLNA) is enabled, the app advertises its media-server name and service information on the local network and allows compatible devices to browse the available shared library without browser pairing. Hostname discovery can also advertise the local browser service. Devices on that network may see these advertisements. Stop sharing, disable discovery, revoke old playback links, or remove library entries to limit access. Files also included through another active library source can remain available through that source.

Folder access and opening files

Phone downloads use app-owned entries in public Downloads or a local folder you explicitly select. SD-card downloads use a selected eligible folder. Adding an existing media folder grants read access for browsing and streaming its contents and eligible subfolders. These operations do not require All files access.

When you choose Open or Share, Android gives the receiving app access to the selected file. That app handles the file under its own policies. Downloads and files in shared folders remain outside the app’s private records and can remain on the device after uninstalling Pocket Torrent.

Developer services, advertising and payments

This version includes no advertising SDK, analytics service, crash-reporting service, developer-operated cloud account, or working donation/payment collection. The app does not send torrent history or media files to a ShireByte Apps backend as part of its implemented features. Network transfers described above still occur when their features are used.

Android, Google Play, your network provider, document providers and apps you choose to open or share files with may process information under their own policies. If you contact ShireByte Apps, the email service and ShireByte Apps receive what you choose to send. Avoid including passwords, private tracker passkeys or playback tokens.

Retention, deletion and your controls

Saved torrent and media records remain locally until you remove them, clear app data or uninstall. Removing a torrent while keeping files leaves the payload on disk; choosing the explicit delete-files action removes that torrent’s managed payload when storage is accessible. Removing a media folder or stopping sharing does not delete its physical files.

You can disable browser/media access, revoke playback links, revoke paired browsers or reset Web UI security, remove library entries, and revoke folder grants using Android settings where available. Revoking a grant does not erase the folder. Clear app data or uninstall to remove app-private settings, certificate identities, browser verifiers, local identifiers, acceptance records and resume data; use the Android Files app separately to remove retained public downloads. No cloud account exists in this version, so there is no in-app cloud-account deletion process.

The app cannot recall files already copied to another device, erase information retained by peers or trackers, or control third-party retention. If you contact support, request deletion of that correspondence through the privacy contact. Support correspondence is retained only as needed to respond to your request and meet applicable obligations.

Security and changes

Android app-private storage, selected-folder permissions, Keystore keys, HTTPS browser controls, phone approval and revocable device credentials limit access. Media playback HTTP and BitTorrent connections are not universally encrypted. Folder-provider behaviour and operating-system restrictions can affect access and background transfers. Browser trust, backup exclusion behaviour and hardware security still need validation on the target devices before public release.

The app and this policy may change. New advertising, analytics, payments, cloud features or other data practices require a policy and disclosure review before release. The update date identifies this policy revision.
